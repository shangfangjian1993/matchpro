# 数据库并发模型

## 当前架构

- **SQLite**:开发 / 单节点 NAS 部署
- **单写者模式**:SQLite 同一时间只允许一个写操作
- `timeout=60` 是等待锁释放的最大时间(秒),不是并发解决方案

## 已知限制

| 场景 | 表现 |
|---|---|
| 采集 + 预测 同时运行 | 正常,锁等待 | 
| 采集 + 回放 + 训练 同时运行 | 可能 `database is locked` |
| 多用户同时写 | 串行化,排队等待 |

## 生产路径

- **PostgreSQL**:生产环境推荐,支持真正的并发写
- **当前配置**:`db.py` 已支持通过 `DATABASE_URL` 切换到 PostgreSQL

## 最佳实践

1. 避免长时间事务(如批量导入时不做其他操作)
2. 大量写入时串行执行(采集 → 训练 → 回放)
3. 未来切换到 PostgreSQL 可获得真正的并发能力
